# `clinnova_fl/apps/client.py`

Root Flower `ClientApp`.
For every incoming message it builds the local dataset and then dispatches to the specific app's client function.

## Objects and functions

### `app = ClientApp()`

### `@app.evaluate() evaluate(msg, context)`, `@app.query() query(msg, context)`, `@app.train() train(msg, context)`

All three follow the same pattern :
```python
custom_config, node_config = get_experiment_and_node_config(msg, context)
dataset_istance = generic.get_dataset(custom_config, node_config)   # clinnova_fl.dataset.generic
# dispatch on context.run_config["app"]
return <specific_fn>(msg, context, dataset_istance)
```

Dispatch table :

| `run_config["app"]` | `query` | `train` | `evaluate` |
|---|---|---|---|
| `flower_hist` | `apps.flower_hist.client.query` | `NotImplementedError` | `NotImplementedError` |
| `flower_ml_tabular` | `NotImplementedError` | `apps.flower_ml_tabular.client.train` | `apps.flower_ml_tabular.client.evaluate` |
| `flower_k_means` | `pass` (broken) | `pass` (broken) | `pass` (broken) |
| other | `ValueError` | `ValueError` | `ValueError` |

Note that the dataset is built *before* dispatching, so a `NotImplementedError` branch still pays the dataset loading cost.

### `get_experiment_and_node_config(msg, context) -> tuple[dict, dict]`

- `custom_config = msg.content.config_records["custom_config"]` if present, else `{}`.
- `node_config` resolution :
    1. if `'simulation'` in `custom_config` → `get_simulated_node_config(context, custom_config)` when truthy, else `{}`;
    2. elif `'run_with_nvflare'` in `custom_config` → `get_nvflare_node_config()` (returns `{}`, placeholder);
    3. else (real deployment, temporary solution) → `toml.load(context.node_config['full_node_config_path'])` if that key exists, else `{}`.
- Returns `(custom_config, node_config)`.

Important: in deployment, a SuperNode must be started with a node config containing `full_node_config_path`, pointing to a TOML that maps `dataset_id -> {dataset_types, dataset_connector_config_file_path}`.

Important: since the server always sets `app_config['simulation']`, branch 1 is always taken when `custom_config` is the forwarded `app_config`. With `simulation = false` this yields an empty `node_config`, which then fails in `get_dataset` (KeyError on `dataset_id`). So the deployment branch (3) is only reached if the server-side app does not forward `simulation`.

### `get_simulated_node_config(context, custom_config) -> dict`

- `node_id = context.node_config['partition-id']` (provided by the Flower simulation engine).
- Requires `custom_config['paths_nodes_config']` (list of paths, one per partition). Generated by `clinnova_fl.cli.write_debug_config`.
- Returns `toml.load(custom_config['paths_nodes_config'][node_id])`.
- Contains leftover debug `pprint.pprint(context)`.

### `get_nvflare_node_config() -> dict`

Placeholder, returns `{}`.

## Interaction with Flower strategies

When a Flower strategy (e.g. `FedAvg`) drives the run, the message content holds `"arrays"` and `"config"` records but **no** `"custom_config"`.
Then `custom_config = {}` and `get_dataset` fails with `KeyError: 'dataset_id'`.
This currently blocks the ML tabular app (see [`flower_ml_tabular/0_flower_ml_tabular_quickstart.md`](./flower_ml_tabular/0_flower_ml_tabular_quickstart.md)).
